## 视觉检查与取舍

沿用已确认的暖灰与苔绿方向。设计参考使用 editorial-greeting（seed 1462575558），保留系统中文字体、方向指针与左右双栏；不引入参考样式中的侧栏和统计卡片。

首页优先回答两个问题：「要去哪里」与「下一步做什么」。常用书签在左侧顶部，待办独立于右侧；手机使用模块按钮切换。数字来自同一份数据：初始 20 个书签、4 个分组，待办 8 项未完成、2 项已完成。

检查后修正了三个细节：手机模块按钮的 ARIA 关联、触控关闭按钮的大小，以及 favicon 加载期间的首字占位。面板和菜单的阴影用于浮层，选中控件使用轻微层次；骨架呼吸只用于数据加载，因此保留设计检查中的相应 WARN。

使用 ego-browser 截图和 axe 替代需要另启浏览器的设计 inspector。截图检查覆盖桌面、平板、手机与编辑器，产物保存在本地 `.qa/`（不入库）。

## 真实 Supabase 联调

在用户配置 `.env.local` 并亲自在页面输入 PIN 后，使用同一账号完成以下验证，没有读取或记录 PIN、访问令牌或配置值：

- 真实登录成功，刷新页面保留会话；主动刷新会话及服务端验证用户成功。
- 新建书签分组、置顶书签及待办，刷新后数据保留；待办详情与北京时间截止时间一致。
- 修改标题、详情、状态和清除截止时间后持久化；完成后撤销恢复到原来的「进行中」。
- 删除分组的事务函数成功执行，原书签迁入未分组；书签仍可编辑。
- 排序事务成功交换两条临时书签的位置。
- 未登录读取三张业务表均返回 HTTP 401 / `42501`；已登录请求伪造 `owner_id` 被 RLS 以 `42501` 拒绝。
- 使用旧 `updated_at` 更新时匹配 0 条记录，新内容保留；模拟编辑期间另一次写入，界面提示冲突并保留未提交草稿。
- 通过页面删除测试书签和待办，查询确认本次临时分组、书签、待办均无残留。

首轮视觉与交互检查使用内存演示数据；以上联调实际访问用户配置的 Supabase 项目。跨账号 SQL 测试仍使用 PGlite 模拟不同用户；本次没有创建第二个真实 Auth 账号。
