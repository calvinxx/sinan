# 司南暖灰版设计与实现方案

版本：v1.0  
日期：2026 年 11 月 4 日  
用途：作为页面设计、前端开发和 Supabase 接入的共同依据。

司南（sinan）是一款面向个人日常使用的浏览器首页工作台，名称寓意「指引方向」：书签帮助找到要去的网站，待办帮助明确接下来要做的事。项目标识统一使用小写 sinan，中文界面名称使用「司南」。产品提供手动录入的书签管理和待办管理。视觉方向采用暖灰底色、苔绿强调色与紧凑列表；桌面首页同时展示书签和待办。前端部署至 GitHub Pages，数据和鉴权使用 Supabase，登录界面只输入 PIN。

暖灰方向、两项核心功能和部署方式已确定。本文中的尺寸、PIN 长度、截止时间默认值和首版范围，是便于直接开发的默认方案，可在原型评审时调整。

## 产品目标和首版范围

打开首页后，用户能够立即找到常用网址、看见需要处理的任务，并快速记录新内容。界面优先服务高频操作：打开书签、新建待办、完成任务。

| 模块 | 首版包含 |
| --- | --- |
| 书签 | 手动新增、编辑、删除；分组；置顶；调整顺序；搜索 |
| 待办 | 标题、纯文本详情、状态、截止时间；新增、编辑、删除；筛选；完成和恢复 |
| 全局 | 统一搜索、快捷键、PIN 登录、保留会话、同步反馈、移动端适配 |
| 部署 | GitHub Pages 静态站点；Supabase Auth、Postgres 和 RLS |

首版聚焦单用户、暖灰浅色主题。深色主题、标签系统、拖拽排序、看板、重复任务、附件、通知推送、离线写入和浏览器书签导入放入后续迭代。日期到期只改变页面内的显示，不承诺浏览器关闭后的提醒。

## 首页结构

桌面使用顶部工具栏和左右双栏。书签约占 60%，待办约占 40%，以任务标题能够完整阅读为约束调整比例。

| 区域 | 内容与作用 |
| --- | --- |
| 顶部左侧 | 小尺寸名称「司南」与日期 |
| 顶部中间 | 搜索入口，提示「搜索书签或待办」，显示快捷键 |
| 顶部右侧 | 新建菜单、设置入口 |
| 左栏上部 | 置顶书签，优先显示常用入口 |
| 左栏下部 | 分组筛选和书签列表 |
| 右栏上部 | 待处理与已完成切换、截止时间筛选、新建待办 |
| 右栏主体 | 按截止时间分组的任务列表 |
| 临时浮层 | 编辑书签的对话框、编辑待办的侧边面板、搜索面板 |

布局示意，内容为示例：

```text

常用书签                                 待处理  已完成

全部  开发  设计  阅读                    逾期
                                         ○ 整理接口说明     昨天
```

主内容最大宽度 1280px，页面居中；桌面左右边距至少 32px，双栏间距 32px。顶部工具栏约 64px 高，主体上方间距 24px。列表随页面自然滚动，首版不引入两个独立滚动区域。

在 1440 × 900 的验收视口中，两个模块的标题、主要操作和首批内容均应可见。置顶区默认显示最多 8 个入口，更多内容通过「展开」显示，避免挤压分组列表。

## 暖灰视觉规范

### 界面文案约束（2026-11-04 更新）

每个区块只保留一个主标题，用布局、间距、字重与对齐表达层级。删除品牌副标语、重复副标题、鼓励性文案和常驻快捷键提示；常用书签直接以顶部网格呈现，不再重复一个区块标题。

只有信息确实缺失时保留一行说明，例如时区、演示数据的保存范围、错误原因和删除后果。网址域名、任务状态及截止时间属于实际数据。移除重复 tooltip，长名称允许换行；字段标签、图标按钮的无障碍名称和弹窗标题继续保留。

界面的辨识度来自暖色纸面、苔绿操作状态、稳定的留白和整齐的行结构。背景使用实色；分组标题、正文和辅助文字形成三个清楚的阅读层级。品牌标记建议采用简化的方向指针，与「司南」字标组合，并复用于站点 favicon；指针保持静态，在小尺寸下仍清晰可辨，用于表达指引方向的含义。

普通文字对其背景以 4.5:1 为最低对比度目标。上述正文与背景约为 13.80:1，辅助文字约为 4.86:1，主按钮白字约为 6.47:1。实现时继续检查实际组件状态；不能通过降低透明度把辅助文字变得难以阅读。

## 书签管理

### 展示和打开

置顶书签采用紧凑网格，显示 favicon 和名称；一般书签采用列表，显示 favicon、名称、域名以及更多菜单。已置顶的书签仍保留在所属分组中。

名称最多显示两行，超出截断；完整名称可在编辑面板查看。默认在新标签页打开书签，保留工作台；提供清楚的可点击区域和键盘焦点。

图标由浏览器依次尝试网站的 `/apple-touch-icon.png`、`/favicon.ico` 和 Google 图标缓存，全部失败后显示名称首字。图标请求统一使用 HTTPS；Google 回退仅传递网站域名，不包含书签路径或参数。不提供手动指定图标地址，也不要求自动抓取网页标题。网址录入后可用域名预填标题，用户可以修改。

### 录入和组织

新增书签包含标题、网址、分组和置顶选项。标题及网址必填，分组为空时归入「未分组」。

网址缺少协议时补全 https，并在保存前展示规范化结果；只允许 http 和 https。相同规范化网址提示「已存在」，允许定位已有书签或明确选择继续保存，不静默覆盖。

分组支持新增、重命名和删除。删除分组时展示受影响数量，确认后把书签移到「未分组」，保留书签内容。该操作在数据库事务中完成。

首版通过菜单中的「上移／下移」调整分组和书签顺序，置顶区保存独立顺序。普通点击直接打开网址，编辑入口放在更多菜单中。单项删除需确认。

## 待办管理

### 字段和状态

| 字段 | 规则 |
| --- | --- |
| 标题 | 必填，去除首尾空白，最多 200 字符 |
| 详情 | 可选纯文本，保留换行，最多 10000 字符 |
| 状态 | 待处理、进行中、已完成 |
| 截止时间 | 可选，日期加时间，精确到分钟 |

新任务默认为「待处理」，不自动设置截止时间。选择日期后，时间输入框显式预填 18:00，可修改或清除整个截止时间。

首版固定使用 Asia/Shanghai 时区，编辑器标注「北京时间」；数据库存 UTC 时间戳，展示与日期分组统一转换为该时区。后续如增加可配置时区，需要统一调整展示和日期边界。

逾期由「未完成且当前时间晚于截止时间」计算，属于时间提示，不新增一个任务状态。页面恢复可见及跨过日期边界时更新分类。

### 列表和筛选

默认查看「待处理」，包括待处理及进行中的任务；切换「已完成」后仅显示已完成任务。截止时间筛选提供「全部／今天／未来七天／无截止时间」。

默认列表按「逾期／今天／之后／无截止时间」分组。各组按截止时间升序，同一时间按创建时间升序；无截止时间按创建时间降序。已完成列表按完成时间降序。

「今天」筛选包含当天到期任务及所有逾期任务，分别标注。未来七天按北京时间从今天零点到第七天结束计算。首版不加入优先级，避免和截止时间形成两套竞争的排序。

任务行显示状态控制、标题和日期。进行中使用环形标记并提供文字说明；完成项显示完成图标及弱化标题。详情在侧边面板中查看和编辑，列表中不铺开长篇文字。

### 编辑和反馈

点击标题打开桌面右侧 440px 宽的编辑面板，支持修改全部字段。面板提供明确的「保存」按钮；有未保存修改时，关闭前提示保存或放弃。移动端使用全屏编辑面板。

点击完成控制立即更新列表，同时发送请求；成功后显示「已完成，可撤销」。撤销窗口为 5 秒，撤销恢复本次操作前的状态。窗口过后仍可在已完成列表重新打开任务，重新打开后设为待处理。

如果写入失败，恢复原状态并展示重试入口。编辑保存失败时保留输入内容；不会显示成功提示，也不会关闭编辑面板。

## 搜索与键盘操作

顶部搜索使用统一面板，结果分为「书签」和「待办」。匹配书签标题、域名、完整网址、分组名称，以及待办标题和详情；英文忽略大小写。

搜索默认覆盖全部记录，已完成任务显示完成标记。书签结果打开网址；任务结果打开详情。无结果时保留搜索词，并提供「添加书签」和「创建待办」入口。

首版面向数百条个人记录，完整加载个人数据后在内存中搜索；不能把只搜索已加载分页误标成搜索全部。记录增长到明显影响加载或输入响应时，再切换服务端检索。

| 快捷键 | 操作 |
| --- | --- |
| Cmd 或 Ctrl + K | 打开统一搜索 |
| Esc | 关闭当前浮层；有未保存编辑时进入放弃修改确认 |
| Enter | 搜索中执行选中结果；表单中遵循对应提交规则 |
| Cmd 或 Ctrl + Enter | 提交当前编辑表单 |

输入框中不拦截普通字母快捷键。中文输入法组合输入期间，Enter 不触发提交。弹层支持键盘遍历、焦点约束和关闭后返回触发位置；仅图标按钮必须有可读名称。

## 动效与响应式

CSS 负责颜色和焦点变化，Motion 仅负责任务行进出与列表位置变化。布局动画与减少动态效果设置可使用 Motion 的现有能力。[布局动画](https://motion.dev/docs/react-layout-animations)、[减少动态效果](https://motion.dev/docs/react-use-reduced-motion)

| 场景 | 默认行为 |
| --- | --- |
| hover 和选中 | 背景色过渡 120ms |
| 菜单与面板 | 淡入或短距离移动 160 至 200ms |
| 任务完成 | 即时标记，然后在约 180ms 内收起该行 |
| 列表重排 | 相邻内容平滑补位，约 180ms |
| 减少动态效果 | 关闭位移与布局动画，保留即时状态反馈 |

首页没有等待动画的阶段，数据可用后立即可操作。shadcn 浮层保留一套统一的进出动画，避免与 Motion 重复控制同一元素。

| 视口宽度 | 布局 |
| --- | --- |
| 1024px 及以上 | 双栏，最小待办栏宽约 360px |
| 768 至 1023px | 单栏，通过「书签／待办」切换；保留各自筛选和滚动位置 |
| 低于 768px | 单栏，左右边距 16px，顶部搜索简化为入口，编辑采用全屏面板 |

桌面两项功能同时可见。小屏首次进入默认书签，之后记住上次选中的模块。模块切换始终显示在页面顶部，并用文字提示未完成任务数。小屏操作菜单始终可发现，不依赖 hover。

## 加载和异常状态

| 状态 | 页面处理 |
| --- | --- |
| 检查会话 | 显示轻量框架；会话确认前不展示私人数据 |
| 首次加载 | 书签和待办区域分别显示与真实行高一致的骨架 |
| 没有书签 | 「添加第一个常用网址」与添加按钮 |
| 没有待办 | 「暂时没有待办」与新建按钮 |
| 当天无任务 | 「今天没有到期任务」，同时保留逾期信息 |
| 单模块读取失败 | 保留另一个模块，失败区域提供重试 |
| 已有数据后断网 | 保留内存中的内容，显示离线提示；暂停写入 |
| 保存失败 | 保留草稿或回滚乐观更新，提供重试 |
| 会话失效 | 清理私人查询缓存，返回登录；未提交草稿仅暂存在当前内存，重新登录同一账号后恢复 |

首版不将书签、任务和详情持久缓存到 localStorage，不建立离线写入队列。筛选偏好可以本地保存，Auth 会话由 Supabase 客户端按配置持久化。主动退出时清理私人缓存和草稿。

## 前端技术和部署

| 层次 | 方案 |
| --- | --- |
| 应用 | React、Vite、TypeScript |
| 样式 | Tailwind CSS 与统一主题变量 |
| 基础组件 | shadcn/ui |
| 图标 | Lucide，网站入口另用 favicon |
| 动效 | CSS 为主，Motion 按需 |
| 数据访问 | supabase-js |
| 服务端状态 | TanStack Query，统一管理加载、刷新、写入与回滚 |
| 表单 | 简单受控表单与 Zod 校验 |
| 托管 | GitHub Pages 与 GitHub Actions |

shadcn 提供可直接修改的组件代码，适合在统一主题下调整按钮、表单和面板。业务对象组合为 BookmarkItem、BookmarkGroup、TodoRow、TodoEditor、GlobalSearch 和 PinLogin，避免把业务逻辑放进基础组件。[shadcn 组件说明](https://ui.shadcn.com/docs)

应用首版使用一个页面和受控面板，不依赖服务器路由重写。部署到仓库子路径时配置 Vite base 为对应仓库路径，GitHub Actions 构建并发布 dist。后续需要独立详情 URL 时优先考虑 hash 路由。[Vite GitHub Pages 部署](https://vite.dev/guide/static-deploy.html#github-pages)

查询在登录后执行，切回窗口时刷新；写入成功后更新或刷新受影响查询。首版采用重新聚焦同步，不引入 Realtime。待办与书签编辑提交携带读到的 updated_at，通过条件更新检测冲突；未匹配到记录时保留草稿并提示重新加载，避免覆盖另一个设备的新修改。

建议目录如下：

```text
src/
  app/                 页面入口、全局布局与 providers
  components/ui/       shadcn 基础组件
  features/bookmarks/  书签展示、表单与数据操作
  features/todos/      待办列表、编辑与数据操作
  features/search/     全局搜索
  features/auth/       PIN 登录与会话
  lib/                 Supabase 客户端、日期与网址处理
  styles/              主题变量与全局样式
supabase/
  migrations/          表结构、约束和 RLS
docs/
  workbench-design.md  本方案
```

GitHub Pages 承载静态前端，Supabase 承担身份验证和数据读写。首页 URL 的配置由用户在浏览器设置中完成；若要替换浏览器的每个新标签页，则需要额外的浏览器设置支持或扩展，不作为网页本身的功能。

## Supabase 数据与 PIN 登录

### 数据模型

三个业务表共同包含 id、owner_id、created_at、updated_at。id 使用 UUID，owner_id 关联 Auth 用户；时间由数据库生成，更新时维护 updated_at。

| 表 | 业务字段 |
| --- | --- |
| bookmark_groups | name、sort_order |
| bookmarks | title、url、group_id 可空、is_pinned、sort_order、pinned_order 可空 |
| todos | title、details、status、due_at 可空、completed_at 可空 |

status 限制为 todo、doing、done；due_at 和 completed_at 使用 timestamptz。完成任务时填写 completed_at，恢复未完成时清空。标题、详情长度和状态一致性同时通过数据库约束保护。

为 owner_id、书签分组与顺序、任务状态与截止时间建立适当索引。书签的 group_id 必须指向同一个 owner 的分组，通过包含 owner_id 的复合外键或等效数据库约束保证；删除分组和迁移书签必须原子执行。

### 登录体验与实现

页面仅展示名称、一个 PIN 输入框与「进入司南」按钮。PIN 使用单个密码输入框，支持粘贴、显示或隐藏、数字键盘提示，不采用逐位跳转的多个输入框。默认方案采用随机生成的至少 8 位数字 PIN，支持更长 PIN。

在 Supabase 中预先创建一个邮箱账号并关闭公开注册，使用 PIN 作为该账号的密码。前端使用预设账号标识与用户输入的 PIN 调用标准密码登录。预设账号标识属于公开配置，不承担保密职责；PIN 只交给 Auth 验证，不进入前端构建、业务表或日志。Supabase 密码登录本身以邮箱或手机号关联身份。[密码登录文档](https://supabase.com/docs/guides/auth/passwords)

这是一项互联网密码认证方案，数字 PIN 的长度和随机性直接影响抗猜测能力。上线前配置密码策略、Auth 服务端限流与 CAPTCHA；前端倒计时仅用于反馈，不能代替服务端限制。标准限流以 IP 等维度工作，不将其描述为按账号永久锁定。[Auth 限流](https://supabase.com/docs/guides/auth/rate-limits)、[CAPTCHA](https://supabase.com/docs/guides/auth/auth-captcha)

登录成功后由客户端保留并刷新会话，再次打开首页通常无需重复输入。提供退出入口，刷新失败时回到登录页面；忘记 PIN 的首版恢复途径由本人通过 Supabase 管理端处理。[会话说明](https://supabase.com/docs/guides/auth/sessions)

### 数据权限

三张业务表全部启用 RLS。读取和删除限制为当前认证用户的记录；插入与更新也校验 owner_id 等于当前 auth.uid()，且更新不能把记录转给其他 owner。未登录请求不能读写私人数据，直接调用 API 同样受这些规则限制。[RLS 文档](https://supabase.com/docs/guides/database/postgres/row-level-security)

前端配置只包含项目 URL、publishable key 和预设账号标识。这些构建变量可以被查看；service-role key、secret key、数据库密码和 PIN 均不放入 Vite 环境变量或静态产物。[Supabase 数据访问说明](https://supabase.com/docs/guides/database/secure-data)

## 实施顺序和验收

| 阶段 | 产出 | 通过条件 |
| --- | --- | --- |
| 视觉原型 | 主题、首页、书签项、任务行、编辑面板 | 用 20 个书签和 10 条任务检查长短文本、首屏密度和小屏布局 |
| 本地交互 | 搜索、表单、筛选、完成与撤销、分组和排序 | 所有首版操作可用，键盘操作和空状态成立 |
| 数据接入 | 数据迁移、RLS、PIN 登录、真实增删改查 | 刷新后数据保留，失败不丢草稿，未授权访问被拒绝 |
| 部署检查 | GitHub Actions、Pages 路径、生产配置 | 静态资源正确加载，登录及读写成功，构建产物无私密配置 |

功能验收覆盖新增、编辑、删除、置顶、排序和分组删除；待办覆盖三种状态、清除截止时间、完成撤销和恢复。时间逻辑重点检查跨午夜、逾期以及北京时间与 UTC 转换。

视觉与可访问性验收至少检查 1440 × 900、1024 × 768 和 390 × 844 三种视口，包含长标题、无图标、空数据、200% 缩放和减少动态效果。要求无页面横向溢出，键盘焦点可见，移动端操作入口不依赖鼠标悬停。

数据验收需要实际发起未登录及非 owner 的读写请求，确认 RLS 拒绝访问；模拟网络失败和两端同时编辑，确认回滚、草稿保留和冲突提示有效。此处是开发验收要求，不代表功能已经实现或上线。
